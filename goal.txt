1. NORTH-STAR GOAL (one sentence)
--------------------------------------------------------------------------------
Build a production-ready, multi-tenant-capable, AI-native Hotel Operating System
in Django 5 + PostgreSQL/pgvector where the AI Receptionist (voice + text + face
+ OCR + RAG) is the primary interface, backed by a complete PMS core
(rooms, reservations, folio/billing, housekeeping, restaurant), operable by a
real hotel every single day without workarounds.

Success is NOT "features demoed". Success is: a pilot hotel runs ASHOS in
parallel with their paper register for one month and then throws the register
away.

2. SOURCE ANALYSIS — WHAT THE THREE INPUTS AGREE / DISAGREE ON
--------------------------------------------------------------------------------

2.1 AGREEMENT (hard requirements, all three sources)
  - AI is the interface, not an add-on. AI Reception = Module #1 priority.
  - Stack: Python 3.13/3.12, Django 5, DRF, Celery, Redis, WebSocket, JWT, RBAC.
  - DB: PostgreSQL + pgvector. Vectors live in the same ACID database.
  - AI: OpenAI-compatible LLM API, RAG, Sentence Transformers, Whisper, TTS,
    CLIP image vectors, InsightFace, PaddleOCR.
  - Frontend: Bootstrap 5 + vanilla ES6 (+ Alpine.js / HTMX). NOT React/Vue.
  - Storage: MinIO / S3-compatible. Deploy: Docker Compose + Nginx + TLS.
  - Modules: AI Reception, Reservation, Rooms, Guest PWA, Housekeeping,
    Restaurant, Billing, AI Center, Vision, RAG + Image Vector Search.
  - Clean architecture: apps/ + api/ + services/ + repositories/.
  - AI Center is the control plane — change AI behaviour with no code deploy.

3. LOCKED TECHNICAL DECISIONS
--------------------------------------------------------------------------------
D01  Python 3.12 (not 3.13/3.14) — torch / paddleocr / insightface wheels are
     not reliably published for 3.13+. Revisit at Phase 3.
D02  Django 5.x + DRF + drf-spectacular (OpenAPI 3.1) + SimpleJWT.
D03  ASGI everywhere (Daphne/Uvicorn) — Channels WebSocket for voice + chat.
D04  PostgreSQL 16 + pgvector, HNSW indexes (not IVFFlat — no training step).
D05  Every table: UUIDv7-style PK, created_at/updated_at, soft delete where it
     matters, tenant_id FK, audit trail on mutating admin actions.
D06  services/ layer holds ALL business logic. Views/serializers/tasks are thin.
     NO view, task, template tag, or model method may call an AI SDK directly.
D07  Single AI gateway: services/ai/ exposes chat(), embed(), transcribe(),
     speak(), caption(). Vendor swap = one config row, zero code change.
D08  Vector dimensions are config-recorded (ai_model_config.dimension). Model
     change => explicit re-embed migration job, never a silent mismatch.
D09  Face pipeline REQUIRES liveness before enrolment or match. No exceptions.
D10  Biometrics are opt-in only, embedding-only (raw image discarded), encrypted
     at rest, with expires_at + a Celery Beat purge job + delete-me API.
D11  AI never executes money movement or refunds. It proposes; a human approves.
D12  Graceful degradation: if the LLM provider is down, the PMS still works in
     manual mode. Kill Switch in AI Center flips it instantly.
D13  Offline: kiosk queues check-ins locally (IndexedDB) and syncs on reconnect.
D14  tests/ai_eval/ regression suite gates every prompt change (>=30 questions).
D15  12-factor config: .env only, no secrets in git, django-environ.
D16  Idempotency-Key header mandatory on payment + booking POSTs.
D17  RFC 7807 problem+json error envelope on all API errors.
D18  Cursor pagination on all list endpoints.

5. PHASE PLAN & EXIT CRITERIA (~30 weeks, buffer included)
--------------------------------------------------------------------------------
P0  FOUNDATION                                            weeks 1-3
    Repo skeleton, settings split, Docker stack (postgres+pgvector, redis,
    minio, web, worker, beat, nginx), custom User + RBAC + audit, DRF + JWT +
    OpenAPI, base templates + design system, services/ai gateway, CI, legal
    check on biometrics, LLM cost/latency PoC.
    EXIT: `docker compose up` gives a login, a themed shell matching the
    prototype, a working /api/v1/ai/health/ round-trip to a real LLM, and a
    measured cost-per-1k-tokens number written into the repo.

P1  CORE PMS (works with AI switched off)                 weeks 4-9
    Rooms/types/rates · Guests · Reservations + availability · manual
    check-in/out · Folio/Invoice/Payments · Dashboard v1 with real KPIs.
    EXIT: a hotel could be run manually on ASHOS. No AI required. No stubs.

P2  AI LAYER                                              weeks 10-16
    AI Center (models, versioned prompts, KB, logs, kill switch) · RAG pipeline
    (chunk, embed, hybrid retrieve, cite) · AI Concierge text · Whisper STT +
    TTS voice loop over WebSocket · avatar · OCR · ai_eval suite.
    EXIT: 50 real guest questions -> >=90% correct answers with citations;
    first-token < 1.5s; voice round-trip < 3s.

P3  VISION & VECTOR SEARCH                                weeks 17-21
    Face detect + liveness + consent enrolment + face check-in · CLIP image
    indexing · semantic image search · AI room recommendation · lost & found.
    EXIT: face match >=95% accuracy in good light, <1s; image search top-5
    relevance >=80% on a 20-query benchmark; every biometric rule in D10 proven
    by an automated test.

P4  GUEST APP & AUTOMATION                                weeks 22-26
    Guest PWA · restaurant + room service · housekeeping priority engine ·
    notifications · proactive checkout reminder (T-12h) · analytics/predictions.
    EXIT: a guest completes order -> bill -> checkout entirely from the phone.

P5  HARDENING & PILOT                                     weeks 27-30
    Load test (100 concurrent sessions, 500 rooms) · security audit ·
    backup/restore drill (RPO 1h / RTO 4h) · docs · staff training · live pilot.
    EXIT: pilot hotel operating daily, without workarounds, for 30 days.

--------------------------------------------------------------------------------
7. DEFINITION OF DONE (every single PR)
--------------------------------------------------------------------------------
  [ ] Business logic lives in services/, not in the view/task/model.
  [ ] Type hints on public functions; docstring says WHY, not what.
  [ ] Unit tests for the service; integration test for the endpoint.
  [ ] Migration included, reversible, and applied cleanly on a fresh DB.
  [ ] OpenAPI schema regenerates without warnings.
  [ ] Permission class + tenant scoping asserted by a test (negative case too).
  [ ] Audit-logged if it mutates money, biometrics, or permissions.
  [ ] No secret, no key, no model weight committed.
  [ ] ruff + black + mypy clean; CI green.
  [ ] If it touches a prompt: tests/ai_eval/ re-run and score not regressed.

9. RISKS & GOVERNANCE
--------------------------------------------------------------------------------
  R1  Biometric law (BD DPA / GDPR for foreign guests)  -> legal sign-off in P0;
      face is OPTIONAL by design so a "no" costs a feature, not the product.
  R2  InsightFace pretrained weights are non-commercial -> licence audit in P0;
      commercial alternative pre-identified before P3 starts.  BLOCKING ITEM.
  R3  LLM cost overrun            -> P0 cost model, caching, cheap-model routing.
  R4  Voice latency               -> streaming, warm connections, edge TTS.
  R5  Scope creep                 -> §4.2 is the contract. Change Request only:
                                     written impact on scope/date/cost, signed,
                                     before any code.
  R6  Hallucination               -> context-only prompt, citations, ai_eval.
  R7  Guest rejects AI            -> "Talk to a human" button on every screen.
  R8  Internet outage             -> offline queue + local fallback.
  R9  Small team / bus factor     -> docs, review, zero undocumented magic.
  R10 LLM vendor lock-in          -> D07 gateway.
